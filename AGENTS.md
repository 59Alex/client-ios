# Правила работы над connect-ios

Действуют общие правила [cnnect-workspace/AGENTS.md](https://github.com/59Alex/cnnect-workspace/blob/main/AGENTS.md):
изменения в `dev` только через PR (squash merge), без прямого push и force-push, секреты только вне Git.

## Перед изменением

- Прочитать `README.md` и соответствующий код веб-клиента `connect-ui` (ветка `dev`) —
  он источник поведения и контрактов API. Расхождения фиксировать в PR.
- Не менять HTTP-контракты сервисов из iOS-задачи; нужные серверные изменения оформлять
  отдельными PR в соответствующих репозиториях с общим ID задачи.

## Код

- Swift 6, строгая конкуренция без предупреждений; `@MainActor @Observable` для моделей экранов.
- Логика и сеть — в `Packages/ConnectKit` без UIKit/SwiftUI, чтобы она тестировалась и на Linux.
  Apple-only API (Keychain и т. п.) закрывать `#if canImport(...)`.
- Зависимости передавать через инициализаторы; синглтоны и сторонние DI-контейнеры не добавлять.
- Сторонние SPM-зависимости добавлять только по согласованию.
- `Connect.xcodeproj` не коммитить: правки проекта — в `project.yml`.

## Визуальные правила

Как в веб-клиенте: однотонные заливки, без градиентов, декоративных теней, blur и тонирующих
наложений. Глубина — разницей яркости canvas/surface и тонкими границами. Цвета только из
`Palette` (Assets.xcassets с light/dark), видимый фокус, цели нажатия не меньше 44×44 pt,
поддержка Dynamic Type и VoiceOver.

## Проверка

- `swift test --package-path Packages/ConnectKit`.
- Изменение UI или поведения считается проверенным только после сборки и прогона XCUITest на
  симуляторе (CI job `ios-simulator`) и просмотра скриншотов из артефакта.
- Новые сценарии экранов покрывать XCUITest на `-ui-test-stub`; реальную сеть в тестах не использовать.
- В PR указывать ссылку на прогон CI и что проверено по скриншотам.
